# modernvroapi.in - Release Notes

## [v1.4.0] - 2026-11-20 - Problem reports from AI agents and readers

### ✨ New Features
- **MCP tool `report_inaccuracy`** (MCP server 1.1.0): when a real Orchestrator contradicts the reference, an agent can send a report in a fixed pattern (plugin, class, member, kind, what the reference says, what happened, Orchestrator version and build, code, error log, suggested fix). The agent must first get the agreement of the person it works for (`user_approved: true`).
- **`POST /api/report`**: the same report over plain HTTP for agents and scripts that do not use MCP. `GET /api/report` lists the fields. Described in `llms.txt`.
- **Reports become public GitHub issues** labelled `agent-report`, titled `[agent-report] <plugin> / <Class>.<member>`. A repeat report for the same target is added as a comment on the open issue.
- **"Report a problem" link on every class page** opens a GitHub issue with the same fields laid out.

### 🔧 Safeguards
- The class must exist in the reference; free text is length-capped, placed in code blocks, and scrubbed of tokens, passwords, host names, IP addresses and e-mail addresses.
- Limits: 5 reports an hour per caller, 40 automatic issues a day site-wide, 10 comments per issue.
- Without the `GITHUB_REPORT_TOKEN` environment variable, or when a limit is hit, nothing is sent and the caller gets a pre-filled GitHub link instead.

### ⚠️ Setup
- Set `GITHUB_REPORT_TOKEN` in the Vercel project: a fine-grained GitHub token limited to this repository with Issues read and write.

## [v1.3.0] - 2026-11-20 - Real URLs and pre-built pages for search engines

### ✨ New Features
- **Real page addresses**: pages moved from `/#/plugin/<id>/class/<Class>` to `/plugin/<id>/class/<Class>`, so every plugin and class has its own URL that search engines can index.
- **Pre-built HTML**: the build now writes a static page for the home page, the MCP page, each plugin and each class (12,845 pages) with the class description, attributes and methods in the HTML, its own title, description, canonical link and structured data. The React app takes over when it loads.
- **`sitemap.xml` and `robots.txt`** are generated on every build.
- **`/?q=term`** opens the home page with the plugin filter filled in.

### 🔧 Improvements
- **Old links keep working**: any `/#/...` link is sent to the new address when the page opens.
- **Titles and descriptions** now mention vRO and VCF Operations Orchestrator and come from one shared module (`src/lib/seoText.ts`) used by both the pages and the pre-render step.
- **No duplicate head tags**: each page has one description, one canonical link and one set of social tags.
- **Saved dark theme is applied before the page paints.**
- **MCP and `/api/v1` `docUrl` values** point to the new addresses.

### ⚠️ Notes
- Asset paths are now absolute (`base: '/'`), so the site must be served from the domain root.
- `vercel.json` sends unknown addresses to `app.html` (the plain app shell) instead of `index.html`.

## [v1.2.3] - 2026-11-20 - Reindex script fixed

### 🐛 Bug Fixes
- **`npm run reindex` is safe to run again**: Azure, Cohesity and VCF Automation for All Apps were missing from `scripts/plugin-names.ts`, so a reindex renamed them to upper-cased fallbacks. The names are now in the list and the script regenerates `index.json` with the same entries as before.
- **Site search finds every plugin**: the search index was missing the Azure and VCF Automation for All Apps plugins and had outdated names for Cohesity and Aria Automation.
- **Cross-references cleaned up**: removed 31 empty entries and the partial `String`, `boolean`, `Number` and `Object` entries that only the Azure plugin had; `VCFAHostManager.getHostBySid` is no longer listed as a parameter usage of `VCFAHost` (it only returns it).

### 🔧 Improvements
- **`scripts/reindex.ts` rewritten**: same output as before, with typed data, set-based de-duplication, a fixed file order and a warning that lists any plugin without a display name.
- **Old `scripts/reindex.js` removed**: an unused copy with an outdated name list.
- **Add-plugin workflow simplified**: the four index files are generated by `npm run reindex` instead of being edited by hand.

## [v1.2.2] - 2026-11-20 - Three more workflow item classes

### ✨ New Features
- **New core classes**: `WorkflowDecisionActivityItem`, `WorkflowForeachItem` and `WorkflowSwitchItem` added to System (Core Classes). They are not listed in the API Explorer.
- **Lab-verified attributes**: every attribute was read on VCF Operations Orchestrator 9.1.1.0 (build 25643527) across 1,236 workflows; behaviour seen in the lab is noted in the attribute descriptions.
- **Switch item note**: `outItems` and `conditions` are Java arrays that must be read with `.length` and `[i]`; passing or returning the array itself throws `InternalError: Invalid JavaScript value`.

## [v1.2.0] - 2026-11-15 - MCP Server

### ✨ New Features
- **MCP server (1.0.0)**: `https://modernvroapi.in/api/mcp`, a remote, read-only Model Context Protocol endpoint (Streamable HTTP, stateless, no auth) with four tools: `search_api`, `get_class`, `list_plugins` and `get_method_signature`.
- **Search index**: `scripts/build-ai-api.mjs` now also writes `/api/v1/search-index.json`, a compact list of every class, method and attribute (used by the MCP search).
- **llms.txt** mentions the MCP endpoint.

### 🔧 Improvements
- The `/api/` CORS and cache headers in `vercel.json` now apply to `/api/v1/` only, so MCP responses are never cached.
- `npm run mcp:test` runs a local smoke test of every tool.

## [v1.1.0] - Azure Plugin Integration & Engine Update

### ✨ New Features
- **Azure Plugin Added**: Fully integrated the official `o11n-plugin-azure` to the modernvroapi.in documentation catalog.
- **Plugin Installation Reference**: Embedded the [official VCF Extensibility Installation Guide](https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-0/configuration-of-vmware-cloud-foundation-operations-orchestrator/vcf-ochestrator-plugins-overview/manage-the-orchestrator-plug-ins/install-update-or-delete-a-plug-in.html) dynamically beside downloadable plugin components across the site.
- **Top Bar Version Marker**: Added dynamic `1.1.0` badge on the global site header navigation.

### 🐛 Bug Fixes
- **Markdown Extraction Resilience**: Fixed a critical extraction bug in `update_docs_from_md.js` where properties lacking descriptions caused tables to collapse and misalignment of `Type` and `Read-only` values. 

### 🔧 Improvements
- **Array Value Type Formatting**: Hardened the conversion scripts to automatically transform clunky `Array/TypeName` syntax into standard `TypeName[]` syntax recursively.
- **Cross-Reference Inheritance for Arrays**: Overhauled the indexing logic (`update-indices`) so methods returning Array structures dynamically anchor back to base classes in the Reference tracking panels.
